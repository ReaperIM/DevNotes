<a id="null-coalescing"></a>
## Значение по умолчанию через ??

**PHP 7.0+ | Ядро**

Используйте `??`, когда отсутствующее значение и `null` означают «взять значение по умолчанию». Существующие `0`, `false` и пустая строка сохраняются. Это удобно для настроек и необязательных полей массива.

```php
$config = ['limit' => 0, 'label' => null];

var_dump( $config['limit'] ?? 20 );
var_dump( $config['label'] ?? 'Untitled' );
var_dump( $config['missing'] ?? 'Fallback' );
# int(0), string(8) "Untitled", string(8) "Fallback"
```

В отличие от `?:`, оператор не заменяет каждое ложное значение. Он также не различает отсутствующий ключ и ключ с `null`; если разница важна, нужен `array_key_exists()`. При сочетании `??` со склеиванием строк явно ставьте скобки.

[Документация PHP](https://www.php.net/manual/en/language.operators.comparison.php#language.operators.comparison.coalesce)

<a id="null-coalescing-assignment"></a>
## Дополнение настроек через ??=

**PHP 7.4+ | Ядро**

`??=` записывает значение по умолчанию обратно в переменную или элемент массива. Он подходит, когда следующий код должен видеть дополненные настройки, а не только временное запасное значение.

```php
$config = ['retries' => 0];
$config['timeout'] ??= 30;
$config['retries'] ??= 3;

echo $config['timeout'], ':', $config['retries'];
# 30:0
```

Элемент с `null` тоже будет заменён. Правая часть вычисляется только тогда, когда нужно присваивание, поэтому там может находиться и более дорогой расчёт значения по умолчанию.

[Документация PHP](https://www.php.net/manual/en/language.operators.assignment.php)

<a id="spaceship"></a>
## Сортировка оператором <=>

**PHP 7.0+ | Ядро**

Функция сравнения для сортировки должна возвращать отрицательное число, ноль или положительное число. `<=>` даёт именно такой результат: `-1`, `0` или `1`. Это убирает цепочку условий из функции сравнения.

```php
$rows = [['score' => 8], ['score' => 2], ['score' => 5]];

usort( $rows, function( array $left, array $right ): int
{
	return $left['score'] <=> $right['score'];
} );

echo implode( ',', array_column($rows, 'score') );
# 2,5,8
```

Для убывающего порядка поменяйте операнды местами. Если типы могут различаться, сначала нормализуйте данные: `<=>` использует правила сравнения PHP и не является оператором строгого равенства. Возврат только `true` или `false` не заменяет трёхстороннее сравнение.

[Документация PHP](https://www.php.net/manual/en/language.operators.comparison.php)

<a id="arrow-functions"></a>
## Стрелочные функции и захваченные значения

**PHP 7.4+ | Ядро**

`fn` удобна для короткого преобразования с одним выражением. Переменные из внешней области захватываются по значению при создании функции; явный список `use` не нужен.

```php
$factor = 10;
$multiply = fn( int $value ): int => $value * $factor;
$factor = 20;

echo $multiply( 3 );
# 30
```

Для нескольких действий используйте обычное замыкание, а для изменения внешней переменной нужно `use( &$value )`. Захват объекта по значению всё ещё ссылается на тот же объект, а не создаёт глубокую копию. `static fn` также не привязывает `$this` автоматически.

[Документация PHP](https://www.php.net/manual/en/functions.arrow.php)

<a id="named-arguments"></a>
## Именованные аргументы

**PHP 8.0+ | Ядро**

Имена параметров делают смысл вызова понятным и позволяют пропускать необязательные параметры. Это особенно удобно для нескольких булевых опций или функций со многими значениями по умолчанию.

```php
function describe_item( string $name, bool $active = true, int $limit = 20 ): string
{
	return $name . ':' . $limit;
}

echo describe_item( 'Report', limit: 5 );
# Report:5
```

Позиционные аргументы должны идти перед именованными. Имена параметров становятся частью интерфейса вызова: переименование `$limit` может сломать код с `limit:`. В публичных функциях выбирайте понятные стабильные имена.

[Документация PHP](https://www.php.net/manual/en/functions.arguments.php#functions.named-arguments)

<a id="unpacking-named-arguments"></a>
## Строковые ключи становятся именованными аргументами

**PHP 8.0+ | Ядро**

При распаковке массива в вызов строковые ключи воспринимаются как имена параметров. Это важно и при переносе кода с `call_user_func_array()` на PHP 8: ассоциативный массив уже не является только позиционным списком.

```php
function format_range( int $start, int $end ): string
{
	return $start . '-' . $end;
}

$arguments = ['end' => 9, 'start' => 3];
echo format_range( ...$arguments );
# 3-9
```

Неизвестные имена или повторная передача одного параметра вызывают ошибку. Если ключи являются произвольными метками, а нужен позиционный порядок, осознанно используйте `array_values()`. Не распаковывайте непроверенные данные запроса прямо в функцию приложения.

[Документация PHP](https://www.php.net/manual/en/function.call-user-func-array.php)

<a id="named-after-unpacking"></a>
## Именованные аргументы после распаковки

**PHP 8.1+ | Ядро**

Вызов может распаковать подготовленный список, а затем передать оставшиеся параметры по имени. Это удобно, когда конкретному вызову нужна явная опция в дополнение к общим позиционным аргументам.

```php
function join_parts( string $left, string $right, string $separator = '/' ): string
{
	return $left . $separator . $right;
}

$parts = ['docs', 'types'];
echo join_parts( ...$parts, separator: ':' );
# docs:types
```

Именованный аргумент в конце не может повторно задавать параметр, который уже передан распакованным массивом. Это возможность аргументов вызова, отдельная от распаковки массивов в другой массив.

[Документация PHP](https://www.php.net/manual/en/functions.arguments.php)

<a id="match"></a>
## match возвращает значение и сравнивает строго

**PHP 8.0+ | Ядро**

`match` удобен, когда небольшой набор входных значений определяет один результат. Каждая выбранная ветка является выражением, а сравнение строгое, поэтому `1` и `'1'` могут давать разные результаты.

```php
$status = '1';
$label = match( $status )
{
	1 => 'numeric',
	'1' => 'text',
	2, 3 => 'other known state',
	default => 'unknown',
};

echo $label;
# text
```

Перехода в следующую ветку и `break` нет. Если нет подходящей ветки и `default`, PHP выбрасывает `UnhandledMatchError`. Отсутствие `default` может быть намеренным, когда нужно обрабатывать каждый случай enum. Заменяя `switch`, проверьте его прежнее нестрогое сравнение.

[Документация PHP](https://www.php.net/manual/en/control-structures.match.php)

<a id="nullsafe"></a>
## Цепочка необязательных объектов через ?->

**PHP 8.0+ | Ядро**

`?->` останавливает цепочку доступа к объектам, если левый операнд равен `null`. Это короткая запись ситуации, когда связанный объект действительно может отсутствовать.

```php
class Profile
{
	public function city(): string
	{
		return 'Kyiv';
	}
}

$profile = null;
echo $profile?->city() ?? 'Not provided';
# Not provided
```

Ставьте `?->` на каждом шаге, который может быть `null`. Оператор не проверяет имена свойств, не превращает `false` в `null` и не скрывает исключения настоящего метода. Он предназначен для чтения: присваивание через такую цепочку не поддерживается. Отсутствие обязательной связи лучше обозначать явной ошибкой.

[Документация PHP](https://www.php.net/manual/en/language.oop5.basic.php#language.oop5.basic.nullsafe)

<a id="throw-expression"></a>
## throw внутри выражения

**PHP 8.0+ | Ядро**

Отсутствующее обязательное значение может сразу вызвать исключение в выражении, которое его читает. Используйте это для коротких проверок с очевидным смыслом.

```php
$config = ['token' => 'local-example'];
$token = $config['token'] ?? throw new InvalidArgumentException( 'Token is required' );

echo $token;
# local-example
```

Приведённая проверка принимает пустую строку, ведь `??` проверяет только отсутствие и `null`. Если пустой токен недопустим, проверьте содержимое отдельно. Для нескольких шагов проверки или более подробной ошибки используйте обычный `if`.

[Документация PHP](https://www.php.net/exceptions)

<a id="closure-from-callable"></a>
## Преобразование callable через Closure::fromCallable()

**PHP 7.1+ | Ядро**

`Closure::fromCallable()` превращает существующий callable в `Closure` и проверяет возможность вызова в текущей области видимости. Это полезно, когда callback поступает как имя функции или массив метода, а API хранит замыкание.

```php
function add_prefix( string $name ): string
{
	return 'note:' . $name;
}

$format = Closure::fromCallable( 'add_prefix' );
echo $format( 'types' ), PHP_EOL;
var_dump( $format instanceof Closure );
# note:types
# bool(true)
```

Некорректный или недоступный callable вызывает `TypeError` при преобразовании. Полученное замыкание сохраняет контекст видимости callable, а не делает произвольный приватный метод публичным. С PHP 8.1 [синтаксис ссылки на функцию](#first-class-callables) даёт то же поведение для callable, записанного непосредственно в коде.

[Документация PHP](https://www.php.net/manual/en/closure.fromcallable.php)

<a id="first-class-callables"></a>
## Синтаксис ссылки на функцию: function_name(...)

**PHP 8.1+ | Ядро**

Буквальная запись `...` создаёт `Closure` вместо вызова функции. Она удобна для передачи известной функции или метода как callback; доступность проверяется при создании.

```php
$normalize = trim(...);
$values = array_map( $normalize, [' one ', ' two '] );

echo implode( ',', $values );
# one,two
```

`$service->handle(...)` также создаёт ссылку на метод в текущей области видимости. Это не распаковка аргументов: после точек нет массива. Запись нельзя совместить с `?->` или использовать как `new ClassName(...)` для создания callback конструктора.

[Документация PHP](https://www.php.net/manual/en/functions.first_class_callable_syntax.php)

<a id="pipe"></a>
## Оператор последовательной обработки |>

**PHP 8.5+ | Ядро**

Оператор передаёт значение слева в callable справа, а результат вызова становится значением всего выражения. Последовательность небольших преобразований читается в порядке выполнения.

```php
$slug = ' PHP Notes '
	|> trim(...)
	|> strtolower(...)
	|> (fn( string $text ): string => str_replace(' ', '-', $text));

echo $slug;
# php-notes
```

Callable должен принимать переданное значение как аргумент. Для функций с дополнительными аргументами или другой позицией значения используйте небольшое замыкание. Цепочка выполняется синхронно, не обрабатывает ошибки вместо вас и не делает длинное преобразование автоматически понятным.

[Документация PHP](https://www.php.net/manual/en/language.operators.functional.php)

<a id="closures-in-constant-expressions"></a>
## Callback в константных выражениях

**PHP 8.5+ | Ядро**

Ссылки на функции и статические замыкания с определёнными ограничениями теперь разрешены там, где PHP требует константное выражение, в том числе в значениях параметров по умолчанию и константах. Callback может получить полезное начальное значение без nullable-параметра и дополнительной ветки инициализации.

```php
function normalize_name( string $name, Closure $normalizer = trim(...) ): string
{
	return $normalizer( $name );
}

echo normalize_name( ' Ada ' );
# Ada
```

Это не разрешает произвольные вызовы функций внутри констант. Выражение создаёт callable, а его тело выполняется позже при вызове. Замыкания в константных выражениях должны быть статическими и не могут захватывать внешние переменные через `use`.

[Документация PHP](https://wiki.php.net/rfc/closures_in_const_expr)

<a id="recursive-closures"></a>
## Рекурсия через Closure::getCurrent()

**PHP 8.5+ | Ядро**

Замыкание может получить собственный экземпляр, который сейчас выполняется. Благодаря этому не нужно захватывать по ссылке переменную, в которую оно будет записано, только ради рекурсивного вызова.

```php
$factorial = static function( int $value ): int
{
	if( $value < 0 )
		throw new InvalidArgumentException( 'Expected a non-negative integer' );

	if( $value <= 1 )
		return 1;

	$current = Closure::getCurrent();
	return $value * $current( $value - 1 );
};

echo $factorial( 5 );
# 120
```

Вызов `Closure::getCurrent()` вне замыкания выбрасывает `Error`. Он упрощает ссылку, а не алгоритм: глубокая рекурсия всё ещё расходует ресурсы, а значение факториала быстро выходит за пределы целого числа.

[Документация PHP](https://www.php.net/manual/en/closure.getcurrent.php)

<a id="trailing-commas"></a>
## Завершающая запятая в вызовах и объявлениях

**PHP 7.3+ | Ядро**

PHP 7.3 разрешает завершающую запятую в вызове функции или метода. PHP 8.0 также разрешает её в объявлениях параметров и списках `use` замыканий. Благодаря этому добавление строки в многострочный список даёт меньшую разницу в Git.

```php
# This call syntax works from PHP 7.3.
echo implode(
	',',
	['one', 'two'],
);
# one,two
```

Завершающая запятая не передаёт дополнительный аргумент. Минимальная версия зависит от места запятой: вызов и объявление функции получили поддержку в разных выпусках.

[Документация PHP](https://www.php.net/manual/en/functions.arguments.php)

<a id="numeric-literals"></a>
## Читаемые числовые литералы

**PHP 7.4+ | Ядро**

Разделители цифр делают лимит или битовую маску понятнее без изменения значения. PHP 8.1 добавляет явный префикс восьмеричных чисел `0o`, поэтому больше не нужно полагаться на незаметный начальный ноль.

```php
$max_bytes = 10_485_760;
$mask = 0b1111_0000;

echo $max_bytes, ':', $mask;
# 10485760:240
```

В PHP 8.1+ `0o644` означает то же, что `0644`, то есть десятичное `420`. Разделители ставят между цифрами; это синтаксис исходного кода, а не формат, который понимает любое преобразование строки в число.

[Документация PHP](https://www.php.net/manual/en/language.types.integer.php)

<a id="group-use"></a>
## Группировка импортов пространства имён

**PHP 7.0+ | Ядро**

Несколько имён из одного пространства имён могут иметь общий префикс в конструкции `use`. Это удобно, когда файл использует несколько связанных классов приложения.

```php
use App\Report\{CsvWriter, JsonWriter};

echo CsvWriter::class, PHP_EOL;
echo JsonWriter::class;
# App\Report\CsvWriter
# App\Report\JsonWriter
```

Пример выводит имена классов, поэтому не требует создания их объектов. Сам импорт не загружает и не создаёт класс. Не стоит собирать огромную группу только ради меньшего количества строк `use`.

[Документация PHP](https://www.php.net/manual/en/language.namespaces.importing.php)

<a id="closure-call"></a>
## Временная привязка замыкания через call()

**PHP 7.0+ | Ядро**

`Closure::call()` вызывает замыкание с временным объектом `$this` и областью видимости его класса. Это бывает полезно в контролируемом коде проверки, когда постоянно перепривязанное замыкание не нужно.

```php
class Counter
{
	private $value = 7;
}

$read = function(): int
{
	return $this->value;
};

echo $read->call( new Counter() );
# 7
```

Статическое замыкание нельзя привязать к `$this`. Доступ к приватному состоянию должен быть осознанным приёмом для инструментов или тестов, а не заменой обычного публичного интерфейса объекта.

[Документация PHP](https://www.php.net/manual/en/closure.call.php)

<a id="static-initializers"></a>
## Выражения в инициализаторах статических локальных переменных

**PHP 8.3+ | Ядро**

Статическую локальную переменную теперь можно инициализировать вызовом функции или другим динамическим выражением. Инициализация происходит, когда выполнение впервые доходит до неё; следующие вызовы используют сохранённое значение.

```php
function next_number(): int
{
	static $number = strlen( 'seed' );
	return ++$number;
}

echo next_number(), ':', next_number();
# 5:6
```

Это удобно для небольшого локального кеша. Такая запись не создаёт кеш, общий для отдельных PHP-запросов. В долгоживущем worker состояние функции может жить гораздо дольше, поэтому данным конкретного запроса нужен явный контроль времени жизни.

[Документация PHP](https://wiki.php.net/rfc/arbitrary_static_variable_initializers)

<a id="exit-callable"></a>
## exit() и die() ведут себя ближе к обычным функциям

**PHP 8.4+ | Ядро**

`exit()` теперь можно использовать как callable, а его аргумент подчиняется обычным правилам типов, включая `strict_types`. Целое число задаёт код завершения процесса; строка выводится перед завершением.

```php
$terminate = exit(...);

var_dump( $terminate instanceof Closure );
# bool(true)
# Calling $terminate(0) would end this script.
```

Пример получает callable без завершения процесса. Старый код, который передаёт массив или другой недопустимый тип, нужно исправить: PHP теперь выбрасывает `TypeError`, а не полагается на старое преобразование. `die()` является псевдонимом с теми же правилами.

[Документация PHP](https://www.php.net/manual/en/migration84.incompatible.php)

<a id="casts-in-constant-expressions"></a>
## Приведение типа в константных выражениях

**PHP 8.5+ | Ядро**

Явное приведение типа теперь разрешено в константных выражениях. Вычисляемая константа может прямо задавать нужное представление без отдельно подготовленного литерала.

```php
const WHOLE_SECONDS = (int)3.9;

echo WHOLE_SECONDS;
# 3
```

Изменилось то, какие выражения можно объявлять, а не правила преобразования: приведение float к int отбрасывает дробную часть. Приведение не является проверкой входных данных, а правильный литерал вроде `const RETRIES = 3` в нём не нуждается.

[Документация PHP](https://www.php.net/manual/en/language.constants.syntax.php)

<a id="global-constant-attributes"></a>
## Атрибуты глобальных констант

**PHP 8.5+ | Ядро**

Атрибуты теперь можно добавлять к константам вне класса, объявленным через `const`. Практический встроенный пример: пометить старую константу настроек как устаревшую и указать замену.

```php
#[Deprecated( 'Use DEFAULT_PAGE_SIZE' )]
const OLD_PAGE_SIZE = 20;
const DEFAULT_PAGE_SIZE = 20;

echo DEFAULT_PAGE_SIZE;
# 20
```

Чтение `OLD_PAGE_SIZE` создало бы сообщение об устаревании. Этот синтаксис не применяется к константам от `define()`. В собственных атрибутах разрешите `Attribute::TARGET_CONSTANT` и читайте метаданные через reflection; PHP не придумывает поведение для метаданных приложения.

[Документация PHP](https://www.php.net/manual/en/migration85.new-features.php)

<a id="approach"></a>
## Отделяйте совместимость от обновления записи

Сначала обеспечьте правильную работу приложения на целевом интерпретаторе. Затем добавляйте новый синтаксис небольшими изменениями, которые легко просмотреть. Если одновременно сменить версию PHP и переписать много логики, причину регрессии найти сложнее.

Зафиксируйте результат для важных входных значений: отсутствующих полей, null, false, 0, '0', пустой строки, пустого массива и некорректных данных. Это разные состояния. Новая запись должна сохранять их смысл, если контракт не меняется осознанно.

<a id="removed-php8"></a>
## Перед переходом с PHP 7 на PHP 8

Проверьте типичные остатки старого кода:

- create_function() и each() устарели в 7.2 и удалены в 8.0. Используйте замыкание и foreach соответственно. Если код намеренно управлял внутренним указателем массива, учтите это при замене.
- Доступ к символам и элементам через фигурные скобки устарел в 7.4 и удалён в 8.0. Используйте квадратные скобки.
- Замените механизм __autoload() на spl_autoload_register().
- Добавьте явные скобки во вложенные тернарные выражения. Вложенные полные тернарные выражения без скобок устарели в 7.4 и не принимаются в 8.0.
- Используйте implode($separator, $parts); исторический обратный порядок аргументов больше не работает в 8.0.
- Методы с именем класса не являются конструкторами в PHP 8. Используйте __construct().

[Устаревшие возможности 7.2](https://www.php.net/manual/en/migration72.deprecated.php), [устаревшие возможности 7.4](https://www.php.net/manual/en/migration74.deprecated.php), [несовместимости 8.0](https://www.php.net/manual/en/migration80.incompatible.php).

<a id="comparisons"></a>
## Сравнения, switch и match

PHP 8 изменил нестрогое сравнение числа с нечисловой строкой. Например, старое выражение 0 == 'foo' сменило результат с true на false. Для числовых строк есть отдельные правила. Конкретные прикладные значения лучше сравнивать через === и !== после осознанной нормализации.

Замена switch на match тоже меняет семантику: switch сравнивает нестрого, match строго. У match нет перехода в следующую ветку, а отсутствие совпадения без default вызывает UnhandledMatchError. Перед заменой проверьте целые числа из БД и строки из HTTP.

[Изменения сравнения в PHP 8](https://www.php.net/manual/en/migration80.incompatible.php#string-number-comparison), [примеры match](01-syntax-and-functions.md#match).

<a id="arguments-errors"></a>
## Аргументы и ошибки стали явнее

В PHP 8 строковые ключи, переданные в call_user_func_array(), становятся именами параметров. Код, ранее игнорировавший эти ключи, может передать другие аргументы или завершиться ошибкой. Если нужна позиционная передача, явно создавайте список.

Многие некорректные аргументы внутренних функций теперь вызывают TypeError или ValueError вместо только предупреждения и запасного результата. catch(Exception) не перехватывает Error; перехватывайте Throwable лишь там, где действительно можно обработать обе категории. Не скрывайте ошибку успешным ответом.

PDO по умолчанию использует исключения с 8.0; mysqli сообщает об ошибках в строгом режиме с 8.1. Проверьте пути отказа, rollback и ответ клиенту. [Примеры БД](10-databases.md), [миграция на 8.0](https://www.php.net/manual/en/migration80.incompatible.php).

<a id="nullable"></a>
## Обозначайте null осознанно

Передача null в параметр скалярного типа, не допускающий null встроенной функции устарела с 8.1 в режиме с неявным преобразованием. Исправьте источник или явно определите смысл отсутствующего значения; слепое приведение к строке может стереть важный null.

Неявные nullable-параметры вроде string $name = null устарели с 8.4. Пишите ?string $name = null либо string|null $name = null, если минимальная версия 8.0. Также проверьте обязательные параметры после необязательных.

[Примеры nullable](02-types.md#nullable), [устаревшие возможности 8.1](https://www.php.net/manual/en/migration81.deprecated.php), [устаревшие возможности 8.4](https://www.php.net/manual/en/migration84.deprecated.php).

<a id="object-state"></a>
## Свойства, сериализация и объекты вместо ресурсов

- С 8.2 создание необъявленных свойств обычных классов устарело, кроме документированных исключений. Стабильные поля объявляйте; для действительно переменных ключей выбирайте явный контейнер. Смотрите [динамические свойства](03-classes-and-objects.md#dynamic-properties).
- Реализация Serializable без новых магических методов устарела с 8.1. __serialize()/__unserialize() существуют с 7.4. В 8.5 __sleep()/__wakeup() отмечены soft-deprecated: это рекомендация для нового кода, а не новое предупреждение во время выполнения. Смотрите [сериализацию](06-json-xml-and-serialization.md).
- Дескрипторы расширений, в том числе cURL и GD, в PHP 8 стали объектами вместо ресурсов. Проверка is_resource() может отклонить правильный результат. Учитывайте документированные тип и признак отказа конкретного API.
- Старая запись интерполяции с долларом перед фигурными скобками устарела в 8.2; используйте обычный $name или {$name}.

[Устаревшие возможности 8.1](https://www.php.net/manual/en/migration81.deprecated.php), [8.2](https://www.php.net/manual/en/migration82.deprecated.php), [8.5](https://www.php.net/manual/en/migration85.deprecated.php).

<a id="php85"></a>
## PHP 8.5: небольшие изменения, которые стоит проверить

Используйте канонические приведения: (bool), (int), (float), (string). Варианты (boolean), (integer), (double), (binary) устарели. Оператор команд в обратных кавычках тоже устарел; выберите API процессов с явными аргументами, а не механически заменяйте одну shell-строку другой.

Использование null как ключа массива устарело. Выясните, имелся в виду отсутствующий ключ или намеренно ключ пустой строки. Увеличение нечисловых строк устарело; для поддерживаемых буквенно-цифровых значений используйте str_increment().

curl_close(), curl_share_close(), finfo_close() и imagedestroy() устарели, поскольку объекты освобождаются автоматически. Освобождение своей ссылки и повторное использование постоянного соединения процессом являются разными вопросами.

Разложение неподдерживаемого значения, например скалярного, теперь вызывает предупреждение. Массивы, null и объекты с нужным доступом через ArrayAccess являются отдельными допустимыми случаями. Успешный lint не находит такие зависимые от данных проблемы. [Официальные устаревшие возможности 8.5](https://www.php.net/manual/en/migration85.deprecated.php), [несовместимости 8.5](https://www.php.net/manual/en/migration85.incompatible.php).

<a id="rewrites"></a>
## Полезные замены и их условия

По ссылкам приведены полные примеры. Это варианты выбора, а не правила автоматической замены.

- [?? / ??=](01-syntax-and-functions.md#null-coalescing): Отсутствие или null означают значение по умолчанию; сохраняйте значимые ноль и false.
- [fn](01-syntax-and-functions.md#arrow-functions): Подходят одно выражение и захват по значению.
- [match](01-syntax-and-functions.md#match): Нужны строгое сравнение и обработка всех вариантов.
- [?->](01-syntax-and-functions.md#nullsafe): Отсутствующий объект действительно должен давать null.
- [enum](03-classes-and-objects.md#enums): Допустимые состояния образуют фиксированный набор.
- [readonly](03-classes-and-objects.md#readonly-properties): Однократная запись является настоящим контрактом; изменяемость вложенных объектов учтена.
- [array_find()](04-arrays-and-iteration.md#predicate-search): Нужен первый подходящий элемент, а не готовый индекс.
- [str_contains()](05-strings-and-unicode.md#string-search): Нужна булева проверка подстроки; поведение пустой подстроки учтено.
- [json_validate()](06-json-xml-and-serialization.md): Только проверка; если данные понадобятся, декодируйте один раз.
- [Randomizer](11-security-and-random.md): Для секретов выберите безопасный движок, для воспроизводимости тестов движок с seed.
- [property hooks](03-classes-and-objects.md#property-hooks): Небольшая логика доступа к свойству; значимые действия остаются методами.
- [clone()](03-classes-and-objects.md#clone-with): Копия с проверенными изменениями свойств и соблюдением доступа.

<a id="verification"></a>
## Проверяйте изменённое поведение

Запустите настоящие тесты приложения на целевой версии: ошибки, отсутствующие записи и повторные вызовы тоже важны. Отдельно проверьте PHP веб-сервера и CLI, загруженные расширения и драйверы БД. Если пропускаете версии, прочитайте руководства для каждого промежуточного перехода. Успешный php -l подтверждает синтаксис, а не правильность приложения.

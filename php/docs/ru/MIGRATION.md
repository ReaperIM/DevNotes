<a id="approach"></a>
## С чего начать обновление

При смене версии сначала смотрим, где старый код может перестать работать или дать другой результат. Новый синтаксис можно добавить позже, когда привычные сценарии уже проверены на нужной версии PHP. Так легче понять, откуда взялась ошибка.

<a id="removed-php8"></a>
## Что больше не работает в PHP 8.0

- Вместо `create_function()` пишем замыкание, вместо `each()` используем `foreach`. Обе функции пометили устаревшими ещё в 7.2, а в 8.0 удалили.
- Индексы в фигурных скобках меняем на квадратные. Старую запись пометили устаревшей в 7.4.
- Вместо `__autoload()` регистрируем загрузчик через `spl_autoload_register()`. Конструктор с именем класса переносим в `__construct()`.
- Во вложенных полных тернарных выражениях явно ставим скобки, чтобы было понятно, что к чему относится.
- У `implode( $separator, $parts )` сначала идёт разделитель, потом массив. Обратный порядок аргументов больше не поддерживается.

[PHP](https://www.php.net/manual/en/migration80.incompatible.php)

<a id="comparisons"></a>
## Где сравнение даст другой результат

В PHP 7 выражение `0 == 'foo'` давало `true`, в PHP 8 уже даст `false`. Если код сравнивает строки и числа через `==`, такие места стоит посмотреть отдельно. У строк с числами свои правила, поэтому обобщать этот пример на все строки нельзя.

При замене `switch` на [`match`](01-syntax-and-functions.md#match) тоже проверяем поведение: `match` сравнивает строго, не переходит в следующую ветку и выбрасывает `UnhandledMatchError`, если совпадения нет и `default` не задан.

[PHP](https://www.php.net/manual/en/migration80.incompatible.php#string-number-comparison)

<a id="arguments-errors"></a>
## Аргументы и обработка ошибок

- С PHP 8 строковые ключи в `call_user_func_array()` считаются именами параметров. Если раньше имена ключей были произвольными, такой вызов нужно проверить.
- Встроенная функция может ответить на неподходящий аргумент исключением `TypeError` или `ValueError`. Обработчик `catch( Exception )` не поймает ошибки из семейства `Error`; для обоих семейств есть `Throwable`.
- PDO с 8.0 по умолчанию выбрасывает исключения. У mysqli с 8.1 включён `MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT`. Если старый код ждал только `false`, пересматриваем обработку ошибки запроса. Подробнее в [заметках по БД](10-databases.md).

[PHP](https://www.php.net/manual/en/migration80.incompatible.php)

<a id="nullable"></a>
## `null` в параметрах

- С 8.1 передавать `null` во встроенную функцию, чей скалярный параметр его не допускает, считается устаревшим в режиме неявного преобразования. Лучше разобраться, откуда взялся `null` и какое значение функция должна получить.
- С 8.4 запись `string $name = null` устарела. Если `null` действительно нужен, пишем это явно: `?string $name = null` или `string|null $name = null` для PHP 8.0+. Подробнее про [типы](02-types.md#nullable).

[PHP](https://www.php.net/manual/en/migration84.deprecated.php)

<a id="object-state"></a>
## Свойства и сохранение объектов

- С 8.2 [динамические свойства](03-classes-and-objects.md#dynamic-properties) устарели. Если код создаёт свойство простым присваиванием, проверяем объявление класса. Исключения: `stdClass`, обработка через `__set()` и разрешение через `AllowDynamicProperties`.
- С 8.1 реализация `Serializable` без `__serialize()`/`__unserialize()` устарела. Эти новые методы есть с 7.4. Старые `__sleep()`/`__wakeup()` в 8.5 помечены как soft-deprecated: их уже советуют заменять, но нового сообщения об устаревании при выполнении нет.
- В PHP 8 cURL и GD возвращают объекты вместо прежних ресурсов. Поэтому старый `is_resource()` может отклонить вполне рабочий объект.
- С 8.2 запись с долларом перед фигурными скобками в строке устарела. Для подстановки оставляем `$name` или `{$name}`.

[PHP](https://www.php.net/manual/en/migration82.deprecated.php)

<a id="php85"></a>
## На что ещё посмотреть в PHP 8.5

- Приведения `(boolean)`, `(integer)`, `(double)` и `(binary)` устарели. Пишем соответственно `(bool)`, `(int)`, `(float)` и `(string)`.
- Выполнение shell-команды через обратные кавычки устарело. Для таких вызовов выбираем явную функцию работы с процессом.
- `null` в качестве ключа массива или ключа для `array_key_exists()` теперь считается устаревшим. Если имелся в виду пустой строковый ключ, передаём `''` явно. Для увеличения нечисловой строки вместо `++` есть `str_increment()`.
- `curl_close()`, `curl_share_close()`, `finfo_close()` и `imagedestroy()` устарели: освобождение теперь связано со временем жизни объекта.
- Разбор скалярного значения через `[]` или `list()` теперь выдаёт предупреждение, а раньше молча заполнял переменные значениями `null`. При этом сам `null` как источник по-прежнему разрешён, и поддерживаемые объекты `ArrayAccess` тоже работают.

[PHP: deprecated](https://www.php.net/manual/en/migration85.deprecated.php) | [PHP: compatibility](https://www.php.net/manual/en/migration85.incompatible.php)

<a id="rewrites"></a>
## Что можно записать удобнее

- [`??` / `??=`](01-syntax-and-functions.md#null-coalescing) подставляют запасное значение, если ключа нет или там `null`. [`fn`](01-syntax-and-functions.md#arrow-functions) удобна для одного выражения и забирает внешние значения по значению.
- [`str_contains()`](05-strings-and-unicode.md#string-search) отвечает, есть ли подстрока. [`array_find()`](04-arrays-and-iteration.md#predicate-search) возвращает первое значение, которое прошло нашу проверку.
- [`json_validate()`](06-json-xml-and-serialization.md#json-validation) пригодится, когда нужно только проверить JSON. Если дальше будем читать данные, достаточно один раз декодировать их с обработкой ошибки.
- [`readonly`](03-classes-and-objects.md#readonly-properties) защищает свойство от нового присваивания, но объект внутри всё ещё может меняться. [Обработчики свойств](03-classes-and-objects.md#property-hooks) позволяют задать поведение при чтении и записи, а [`clone()`](03-classes-and-objects.md#clone-with) создаёт копию с выбранными изменениями.

<a id="verification"></a>
## Перед выпуском

На нужной версии PHP проверяем обычный сценарий и то, что происходит при ошибке. Отдельно смотрим случаи с `0`, `null` и `false`, если у них разный смысл в нашем коде: именно такие значения легко случайно смешать при обновлении.

<a id="weak-reference"></a>

## Следим за объектом, не удерживая его в памяти

**PHP 7.4+ | Ядро** [Документация PHP](https://www.php.net/manual/en/class.weakreference.php)

Обычная ссылка на объект удерживает его в памяти. Если нужно только наблюдать, существует ли объект ещё, можно создать `WeakReference`. Пока объект кому-то нужен, `get()` его возвращает. В примере после `unset()` обычной ссылки больше нет, поэтому следующий `get()` уже возвращает `null`.

```php
# Наблюдатель не должен продлевать жизнь объекта.
$object = new stdClass();
$reference = WeakReference::create( $object );
var_dump( $reference->get() === $object ); # bool(true)
unset( $object );
var_dump( $reference->get() ); # NULL
```

Если сохранить результат `get()` в обычную переменную, эта переменная снова будет удерживать объект. Слабой остаётся сама `WeakReference`, а не все ссылки, которые мы из неё получили.

<a id="weak-map"></a>

## Кеш, который не удерживает объект ради ключа

**PHP 8.0+ | Ядро** [Документация PHP](https://www.php.net/manual/en/class.weakmap.php)

`WeakMap` позволяет привязать к объекту дополнительные данные, например результат вычисления, и не удерживать сам объект ради кеша. Объект используется как ключ. Когда он больше никому не нужен и уничтожается, его запись исчезает из `WeakMap` автоматически.

```php
$cache = new WeakMap();
$object = new stdClass();
$cache[$object] = ['rendered' => 'ready'];
var_dump( count($cache) ); # int(1)
unset( $object );
var_dump( count($cache) ); # int(0)
```

В примере после `unset()` число записей меняется с одной на ноль. Но значения в `WeakMap` удерживаются обычными ссылками. Если само сохранённое значение ссылается на свой ключ, оно может оставить объект в памяти и запись не исчезнет.

## Пауза и продолжение функции через `Fiber`

**PHP 8.1+ | Ядро** [Документация PHP](https://www.php.net/manual/en/language.fibers.php)

`Fiber` позволяет поставить выполнение функции на паузу и потом продолжить с того же места. Сохраняется и цепочка вложенных вызовов, поэтому приостановиться можно не только в самой внешней функции. Здесь `start()` доходит до `suspend()` и отдаёт наружу строку `'waiting'`.

```php
$fiber = new Fiber( function(): int
{
	$value = Fiber::suspend( 'waiting' );
	return $value * 2;
} );

echo $fiber->start(), "\n"; # waiting
var_dump( $fiber->resume(21) ); # NULL: функция уже завершилась
var_dump( $fiber->getReturn() ); # int(42)
```

Затем `resume(21)` продолжает выполнение: внутри значение `21` становится результатом `suspend()`. Функция возвращает `42`, но её окончательный результат читается через `getReturn()`, поэтому сам `resume()` здесь даёт `null`. Fiber не переключает работу самостоятельно: без планировщика и неблокирующего ввода-вывода обычная блокирующая операция по-прежнему остановит выполнение.

<a id="preloading"></a>

## Предварительная загрузка постоянного кода

**PHP 7.4+ | OPcache** [Документация PHP](https://www.php.net/manual/en/opcache.preloading.php)

Если выбранные функции и классы нужны постоянно, их можно загрузить заранее при старте процесса. В `opcache.preload` задаём путь к PHP-скрипту, который подготовит этот код один раз. В примере такой скрипт компилирует файл с классом, чтобы его определения были доступны следующим запросам.

<!-- example: fragment -->
```php
# Этот preload.php указан в opcache.preload в php.ini.
opcache_compile_file( __DIR__ . '/src/User.php' );
```

В Windows preloading не поддерживается. И замена предварительно загруженного файла сама по себе не обновит определения: после изменения такого кода нужно перезапустить процесс.

<a id="jit"></a>

## Чем отличаются JIT и OPcache

**PHP 8.0+ JIT | OPcache** [Документация PHP](https://www.php.net/manual/en/opcache.configuration.php)

OPcache сохраняет уже скомпилированный байткод, чтобы PHP не компилировал его заново. JIT решает другую часть задачи: может перевести подходящие участки выполнения в машинный код. В примере читаем состояние OPcache и берём данные о JIT, если они вообще есть.

```php
$status = opcache_get_status( false );
$jit = ($status === false) ? null : ($status['jit'] ?? null);
var_dump( $jit ); # Результат зависит от текущего окружения.
```

Польза JIT зависит от нагрузки, а доступность от сборки и настроек. Сам факт его наличия ещё не означает ускорение конкретного кода. При измерении в CLI отдельно проверяем `opcache.enable_cli` и параметры JIT, иначе можно измерять совсем другое окружение.

<a id="ffi"></a>

## Работа с C через `FFI`

**PHP 7.4+ | FFI** [Документация PHP](https://www.php.net/manual/en/book.ffi.php)

`FFI` позволяет описывать типы и функции C и работать с ними из PHP. Это нужно, когда требуется прямое обращение к нативному коду. Здесь пример минимальный, без загрузки библиотеки: создаём значение типа C `int`, записываем в него `42` и читаем обратно.

<!-- example: fragment -->
```php
$ffi = FFI::cdef();
$value = $ffi->new( 'int' );
$value->cdata = 42;
var_dump( $value->cdata ); # int(42)
```

Доступ может ограничиваться настройкой `ffi.enable`. При работе с C неверное описание функции или ошибка обращения к памяти может завершить весь процесс, поэтому обычные гарантии безопасности PHP здесь уже не спасают.

<a id="ini-quantities"></a>

## Разбор размеров из `php.ini`

**PHP 8.2+ | Ядро** [Документация PHP](https://www.php.net/manual/en/function.ini-parse-quantity.php)

Значение вроде `128M` из `php.ini` нельзя просто привести к `int`, если нужен размер в байтах. Для этого есть `ini_parse_quantity()`: он понимает множители `K`, `M` и `G`, где каждый шаг равен 1024. В примере видно, какие числа получаются из `128M` и `512K`.

```php
var_dump( ini_parse_quantity('128M') ); # int(134217728)
var_dump( ini_parse_quantity('512K') ); # int(524288)
var_dump( ini_parse_quantity('-1') ); # int(-1)
```

Специальные значения тоже сохраняем по смыслу настройки: например, `-1` у `memory_limit` не является размером в байтах. Неверная строка может вызвать предупреждение и всё же вернуть число по её началу, поэтому это не строгая проверка произвольного ввода.

<a id="measure-memory"></a>

## Измеряем пик памяти отдельного этапа

**PHP 8.2+ | Ядро** [Документация PHP](https://www.php.net/manual/en/function.memory-reset-peak-usage.php)

Если до нужного участка уже была тяжёлая операция, общий пик памяти будет показывать её результат. `memory_reset_peak_usage()` позволяет начать отсчёт пика заново перед отдельным этапом. Здесь сбрасываем его, создаём строку и считаем, насколько максимум вырос относительно исходного расхода.

```php
# Предыдущие операции не должны задавать пик этого этапа.
memory_reset_peak_usage();
$before = memory_get_usage();
$buffer = str_repeat( 'x', 1_000_000 );
$peak_growth = memory_get_peak_usage() - $before;
var_dump( $peak_growth ); # Рост пика в байтах относительно начала этапа.
unset( $buffer );
```

Сброс не освобождает память и не обнуляет сам расход процесса. `memory_get_peak_usage()` всё ещё возвращает абсолютное число байтов, поэтому для роста в примере вычитаем `$before`.

<a id="ini-and-cli"></a>

## Запасные значения в `php.ini`, права журнала и `php -l`

**PHP 8.2+ права журнала / PHP 8.3+ запасные значения ini и проверка нескольких файлов** [Документация PHP](https://www.php.net/manual/en/configuration.file.php)

С PHP 8.3 в `php.ini` можно указать запасное значение переменной среды: здесь без `PHP_MAX_EXECUTION_TIME` возьмётся `30`. В той же версии `php -l` научился проверять несколько файлов одним вызовом. А `error_log_mode`, доступный с PHP 8.2, задаёт права при создании файла журнала.

```ini
max_execution_time = ${PHP_MAX_EXECUTION_TIME:-30}
error_log_mode = 0640
```

```sh
php -l first.php second.php
```

`0640` в примере задаёт Unix-права. На Windows доступ к файлу настраивается через ACL отдельно, эта запись такие права не заменяет.

<a id="extension-capabilities"></a>

## Проверка возможностей сборки: AVIF в GD

**PHP 8.1+ AVIF API | gd** [Документация PHP](https://www.php.net/manual/en/function.imageavif.php)

Функции работы с AVIF есть в GD с PHP 8.1, но конкретная сборка GD может быть без этого кодека. Поэтому сначала проверяем `imagetypes() & IMG_AVIF` и только потом читаем файл. В примере после чтения сохраняем изображение в другой AVIF-файл.

<!-- example: fragment -->
```php
# Оба пути локальные и уже проверены, не берём их напрямую из запроса.
if( !(imagetypes() & IMG_AVIF) )
	throw new RuntimeException( 'AVIF support is unavailable' );

$image = imagecreatefromavif( $source_path );

if( $image === false )
	throw new RuntimeException( 'Cannot decode AVIF' );

imageavif( $image, $target_path, 80 );
```

Версия PHP и наличие нужного метода ещё не гарантируют поддержку самого формата. Проверка текущей сборки помогает отличить отсутствие кодека от ошибки чтения конкретного файла.

## Измеряем время работы через `hrtime()`

**PHP 7.3+ | standard** [Документация PHP](https://www.php.net/manual/en/function.hrtime.php)

Для длительности операции удобнее `hrtime()`: эти часы идут последовательно и не зависят от перевода календарного времени. Берём значение до вычисления и после, вычитаем одно из другого и переводим наносекунды в миллисекунды. Это время выполнения операции, а не дата для журнала.

```php
$started_at = hrtime( true );
$digest = hash( 'sha256', str_repeat('x', 100000) );
$finished_at = hrtime( true );

if( $started_at === false || $finished_at === false )
	throw new RuntimeException( 'Clock unavailable' );

$elapsed_ms = ($finished_at - $started_at) / 1000000;
var_dump( $elapsed_ms ); # Миллисекунды выполнения; при каждом запуске число своё.
```

При `true` результат имеет тип `int` на 64-битной платформе и `float` на 32-битной. Единица измерения в наносекундах не означает, что оборудование действительно различает каждую наносекунду. Полученные значения проверяем на `false`, как в примере.

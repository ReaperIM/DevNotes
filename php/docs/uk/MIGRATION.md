<a id="approach"></a>
## Відокремлюйте сумісність від осучаснення

Спочатку забезпечте правильну роботу застосунку на цільовому інтерпретаторі. Потім додавайте новий синтаксис невеликими змінами, які легко переглянути. Якщо одночасно змінити версію PHP і переписати багато логіки, причину регресії знайти складніше.

Зафіксуйте результат для важливих вхідних значень: відсутніх полів, null, false, 0, '0', порожнього рядка, порожнього масиву та некоректних даних. Це різні стани. Новий запис має зберігати їхній сенс, якщо контракт не змінюється свідомо.

<a id="removed-php8"></a>
## Перед переходом із PHP 7 на PHP 8

Перевірте типові залишки старого коду:

- create_function() та each() застаріли у 7.2 й видалені у 8.0. Використовуйте замикання та foreach відповідно. Якщо код навмисно керував внутрішнім вказівником масиву, врахуйте це під час заміни.
- Доступ до символів і елементів через фігурні дужки застарів у 7.4 та видалений у 8.0. Використовуйте квадратні дужки.
- Замініть механізм __autoload() на spl_autoload_register().
- Додайте явні дужки до вкладених тернарних виразів. Вкладені повні тернарні вирази без дужок застаріли у 7.4 й не приймаються у 8.0.
- Використовуйте implode($separator, $parts); історичний зворотний порядок аргументів більше не працює у 8.0.
- Методи з назвою класу не є конструкторами у PHP 8. Використовуйте __construct().

[Застарілі можливості 7.2](https://www.php.net/manual/en/migration72.deprecated.php), [застарілі можливості 7.4](https://www.php.net/manual/en/migration74.deprecated.php), [несумісності 8.0](https://www.php.net/manual/en/migration80.incompatible.php).

<a id="comparisons"></a>
## Порівняння, switch та match

PHP 8 змінив нестроге порівняння числа з нечисловим рядком. Наприклад, старий вираз 0 == 'foo' змінив результат із true на false. Для числових рядків є окремі правила. Конкретні прикладні значення краще порівнювати через === та !== після свідомої нормалізації.

Заміна switch на match також змінює семантику: switch порівнює нестрого, match суворо. У match немає переходу до наступної гілки, а відсутній збіг без default спричиняє UnhandledMatchError. Перед заміною перевірте цілі числа з БД і рядки з HTTP.

[Зміни порівняння у PHP 8](https://www.php.net/manual/en/migration80.incompatible.php#string-number-comparison), [приклади match](01-syntax-and-functions.md#match).

<a id="arguments-errors"></a>
## Аргументи та помилки стали явнішими

У PHP 8 рядкові ключі, передані в call_user_func_array(), стають назвами параметрів. Код, який раніше ігнорував ці ключі, може передати інші аргументи чи завершитися помилкою. Якщо потрібна позиційна передача, явно створюйте список.

Багато некоректних аргументів внутрішніх функцій тепер спричиняють TypeError або ValueError замість лише попередження та запасного результату. catch(Exception) не перехоплює Error; перехоплюйте Throwable лише там, де справді можна обробити обидві категорії. Не приховуйте помилку успішною відповіддю.

PDO за замовчуванням використовує винятки від 8.0; mysqli повідомляє про помилки у строгому режимі від 8.1. Перевірте шляхи відмови, rollback і відповідь клієнту. [Приклади БД](10-databases.md), [міграція на 8.0](https://www.php.net/manual/en/migration80.incompatible.php).

<a id="nullable"></a>
## Позначайте null свідомо

Передавання null у параметр скалярного типу, який не допускає null вбудованої функції застаріло від 8.1 у режимі з неявним перетворенням. Виправте джерело чи явно визначте сенс відсутнього значення; сліпе приведення до рядка може стерти важливий null.

Неявні nullable-параметри на кшталт string $name = null застаріли від 8.4. Пишіть ?string $name = null або string|null $name = null, якщо мінімальна версія 8.0. Також перевірте обов'язкові параметри після необов'язкових.

[Приклади nullable](02-types.md#nullable), [застарілі можливості 8.1](https://www.php.net/manual/en/migration81.deprecated.php), [застарілі можливості 8.4](https://www.php.net/manual/en/migration84.deprecated.php).

<a id="object-state"></a>
## Властивості, серіалізація та об'єкти замість ресурсів

- Від 8.2 створення неоголошених властивостей звичайних класів застаріло, крім задокументованих винятків. Сталі поля оголошуйте; для справді змінних ключів обирайте явний контейнер. Дивіться [динамічні властивості](03-classes-and-objects.md#dynamic-properties).
- Реалізація Serializable без нових магічних методів застаріла від 8.1. __serialize()/__unserialize() існують від 7.4. У 8.5 __sleep()/__wakeup() позначено soft-deprecated: це рекомендація для нового коду, а не нове попередження під час виконання. Дивіться [серіалізацію](06-json-xml-and-serialization.md).
- Дескриптори розширень, зокрема cURL та GD, у PHP 8 стали об'єктами замість ресурсів. Перевірка is_resource() може відхилити правильний результат. Враховуйте задокументовані тип і ознаку відмови конкретного API.
- Старий запис інтерполяції з доларом перед фігурними дужками застарів у 8.2; використовуйте звичайний $name або {$name}.

[Застарілі можливості 8.1](https://www.php.net/manual/en/migration81.deprecated.php), [8.2](https://www.php.net/manual/en/migration82.deprecated.php), [8.5](https://www.php.net/manual/en/migration85.deprecated.php).

<a id="php85"></a>
## PHP 8.5: невеликі зміни, які варто перевірити

Використовуйте канонічні приведення: (bool), (int), (float), (string). Варіанти (boolean), (integer), (double), (binary) застаріли. Оператор команд у зворотних лапках також застарів; оберіть API процесів з явними аргументами, а не механічно замінюйте один shell-рядок іншим.

Використання null як ключа масиву застаріло. З'ясуйте, чи йшлося про відсутній ключ, чи свідомо про ключ порожнього рядка. Збільшення нечислових рядків застаріло; для підтримуваних буквено-цифрових значень використовуйте str_increment().

curl_close(), curl_share_close(), finfo_close() та imagedestroy() застаріли, оскільки об'єкти звільняються автоматично. Звільнення свого посилання й повторне використання постійного з'єднання процесом є різними питаннями.

Розкладання непідтримуваного значення, наприклад скалярного, тепер спричиняє попередження. Масиви, null та об'єкти з потрібним доступом через ArrayAccess є окремими допустимими випадками. Успішний lint не знаходить такі залежні від даних проблеми. [Офіційні застарілі можливості 8.5](https://www.php.net/manual/en/migration85.deprecated.php), [несумісності 8.5](https://www.php.net/manual/en/migration85.incompatible.php).

<a id="rewrites"></a>
## Корисні заміни та їхні умови

За посиланнями наведено повні приклади. Це варіанти вибору, а не правила автоматичної заміни.

- [?? / ??=](01-syntax-and-functions.md#null-coalescing): Відсутність чи null означають типове значення; зберігайте важливі нуль та false.
- [fn](01-syntax-and-functions.md#arrow-functions): Підходять один вираз і захоплення за значенням.
- [match](01-syntax-and-functions.md#match): Потрібні суворе порівняння й обробка всіх варіантів.
- [?->](01-syntax-and-functions.md#nullsafe): Відсутній об'єкт справді має давати null.
- [enum](03-classes-and-objects.md#enums): Дозволені стани утворюють фіксований набір.
- [readonly](03-classes-and-objects.md#readonly-properties): Одноразовий запис є справжнім контрактом; змінність вкладених об'єктів врахована.
- [array_find()](04-arrays-and-iteration.md#predicate-search): Потрібен перший відповідний елемент, а не готовий індекс.
- [str_contains()](05-strings-and-unicode.md#string-search): Потрібна булева перевірка підрядка; поведінку порожнього підрядка враховано.
- [json_validate()](06-json-xml-and-serialization.md): Лише перевірка; якщо дані будуть потрібні, декодуйте один раз.
- [Randomizer](11-security-and-random.md): Для секретів оберіть безпечний рушій, для відтворюваності тестів рушій із seed.
- [property hooks](03-classes-and-objects.md#property-hooks): Невелика логіка доступу до властивості; значні дії залишаються методами.
- [clone()](03-classes-and-objects.md#clone-with): Копія з перевіреними змінами властивостей і дотриманням доступу.

<a id="verification"></a>
## Перевіряйте змінену поведінку

Запустіть справжні тести застосунку на цільовій версії: помилки, відсутні записи та повторні виклики також важливі. Окремо перевірте PHP вебсервера й CLI, завантажені розширення та драйвери БД. Якщо пропускаєте версії, прочитайте посібники для кожного проміжного переходу. Успішний php -l підтверджує синтаксис, а не правильність застосунку.

<a id="approach"></a>
## З чого почати оновлення

Під час зміни версії спочатку дивимося, де старий код може перестати працювати або дати інший результат. Новий синтаксис можна додати пізніше, коли звичні сценарії вже перевірені на потрібній версії PHP. Так легше зрозуміти, звідки взялася помилка.

<a id="removed-php8"></a>
## Що більше не працює в PHP 8.0

- Замість `create_function()` пишемо замикання, замість `each()` використовуємо `foreach`. Обидві функції позначили застарілими ще у 7.2, а у 8.0 видалили.
- Індекси у фігурних дужках змінюємо на квадратні. Старий запис позначили застарілим у 7.4.
- Замість `__autoload()` реєструємо завантажувач через `spl_autoload_register()`. Конструктор з іменем класу переносимо в `__construct()`.
- У вкладених повних тернарних виразах явно ставимо дужки, щоб було зрозуміло, що до чого належить.
- У `implode( $separator, $parts )` спочатку йде роздільник, потім масив. Зворотний порядок аргументів більше не підтримується.

[PHP](https://www.php.net/manual/en/migration80.incompatible.php)

<a id="comparisons"></a>
## Де порівняння дасть інший результат

У PHP 7 вираз `0 == 'foo'` давав `true`, у PHP 8 вже дасть `false`. Якщо код порівнює рядки й числа через `==`, такі місця варто подивитися окремо. У рядків із числами свої правила, тому узагальнювати цей приклад на всі рядки не можна.

Під час заміни `switch` на [`match`](01-syntax-and-functions.md#match) теж перевіряємо поведінку: `match` порівнює суворо, не переходить до наступної гілки й викидає `UnhandledMatchError`, якщо збігу немає й `default` не задано.

[PHP](https://www.php.net/manual/en/migration80.incompatible.php#string-number-comparison)

<a id="arguments-errors"></a>
## Аргументи й обробка помилок

- Із PHP 8 рядкові ключі в `call_user_func_array()` вважаються іменами параметрів. Якщо раніше імена ключів були довільними, такий виклик потрібно перевірити.
- Вбудована функція може відповісти на невідповідний аргумент винятком `TypeError` або `ValueError`. Обробник `catch( Exception )` не впіймає помилки із сімейства `Error`; для обох сімейств є `Throwable`.
- PDO з 8.0 типово викидає винятки. У mysqli з 8.1 увімкнено `MYSQLI_REPORT_ERROR | MYSQLI_REPORT_STRICT`. Якщо старий код чекав лише `false`, переглядаємо обробку помилки запиту. Докладніше в [нотатках про БД](10-databases.md).

[PHP](https://www.php.net/manual/en/migration80.incompatible.php)

<a id="nullable"></a>
## `null` у параметрах

- Із 8.1 передавати `null` у вбудовану функцію, чий скалярний параметр його не допускає, вважається застарілим у режимі неявного перетворення. Краще розібратися, звідки взявся `null` і яке значення функція має отримати.
- Із 8.4 запис `string $name = null` застарів. Якщо `null` справді потрібен, пишемо це явно: `?string $name = null` або `string|null $name = null` для PHP 8.0+. Докладніше про [типи](02-types.md#nullable).

[PHP](https://www.php.net/manual/en/migration84.deprecated.php)

<a id="object-state"></a>
## Властивості та збереження об’єктів

- Із 8.2 [динамічні властивості](03-classes-and-objects.md#dynamic-properties) застаріли. Якщо код створює властивість простим присвоєнням, перевіряємо оголошення класу. Винятки: `stdClass`, обробка через `__set()` і дозвіл через `AllowDynamicProperties`.
- Із 8.1 реалізація `Serializable` без `__serialize()`/`__unserialize()` застаріла. Ці нові методи є з 7.4. Старі `__sleep()`/`__wakeup()` у 8.5 позначено як soft-deprecated: їх уже радять замінювати, але нового повідомлення про застарівання під час виконання немає.
- У PHP 8 cURL і GD повертають об’єкти замість колишніх ресурсів. Тому старий `is_resource()` може відхилити цілком робочий об’єкт.
- Із 8.2 запис із доларом перед фігурними дужками в рядку застарів. Для підстановки залишаємо `$name` або `{$name}`.

[PHP](https://www.php.net/manual/en/migration82.deprecated.php)

<a id="php85"></a>
## На що ще подивитися в PHP 8.5

- Перетворення `(boolean)`, `(integer)`, `(double)` і `(binary)` застаріли. Пишемо відповідно `(bool)`, `(int)`, `(float)` і `(string)`.
- Виконання shell-команди через зворотні лапки застаріло. Для таких викликів вибираємо явну функцію роботи з процесом.
- `null` як ключ масиву або ключ для `array_key_exists()` тепер вважається застарілим. Якщо мався на увазі порожній рядковий ключ, передаємо `''` явно. Для збільшення нечислового рядка замість `++` є `str_increment()`.
- `curl_close()`, `curl_share_close()`, `finfo_close()` і `imagedestroy()` застаріли: звільнення тепер пов’язане з часом життя об’єкта.
- Розбір скалярного значення через `[]` або `list()` тепер видає попередження, а раніше мовчки заповнював змінні значеннями `null`. При цьому сам `null` як джерело досі дозволений, і підтримувані об’єкти `ArrayAccess` теж працюють.

[PHP: deprecated](https://www.php.net/manual/en/migration85.deprecated.php) | [PHP: compatibility](https://www.php.net/manual/en/migration85.incompatible.php)

<a id="rewrites"></a>
## Що можна записати зручніше

- [`??` / `??=`](01-syntax-and-functions.md#null-coalescing) підставляють запасне значення, якщо ключа немає або там `null`. [`fn`](01-syntax-and-functions.md#arrow-functions) зручна для одного виразу й бере зовнішні значення за значенням.
- [`str_contains()`](05-strings-and-unicode.md#string-search) відповідає, чи є підрядок. [`array_find()`](04-arrays-and-iteration.md#predicate-search) повертає перше значення, яке пройшло нашу перевірку.
- [`json_validate()`](06-json-xml-and-serialization.md#json-validation) стане в пригоді, коли потрібно лише перевірити JSON. Якщо далі читатимемо дані, достатньо один раз декодувати їх з обробкою помилки.
- [`readonly`](03-classes-and-objects.md#readonly-properties) захищає властивість від нового присвоєння, але об’єкт усередині все ще може змінюватися. [Обробники властивостей](03-classes-and-objects.md#property-hooks) дозволяють задати поведінку під час читання й запису, а [`clone()`](03-classes-and-objects.md#clone-with) створює копію з вибраними змінами.

<a id="verification"></a>
## Перед випуском

На потрібній версії PHP перевіряємо звичайний сценарій і те, що відбувається під час помилки. Окремо дивимося випадки з `0`, `null` і `false`, якщо вони мають різний зміст у нашому коді: саме такі значення легко випадково змішати під час оновлення.

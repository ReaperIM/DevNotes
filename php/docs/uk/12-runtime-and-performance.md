<a id="weak-reference"></a>

## Стежимо за об’єктом, не утримуючи його в пам’яті

**PHP 7.4+ | Ядро** [Документація PHP](https://www.php.net/manual/en/class.weakreference.php)

Звичайне посилання на об'єкт утримує його в пам'яті. Якщо потрібно лише спостерігати, чи існує об'єкт ще, можна створити `WeakReference`. Поки об'єкт комусь потрібен, `get()` його повертає. У прикладі після `unset()` звичайного посилання більше немає, тому наступний `get()` уже повертає `null`.

```php
# Спостерігач не має подовжувати життя об’єкта.
$object = new stdClass();
$reference = WeakReference::create( $object );
var_dump( $reference->get() === $object ); # bool(true)
unset( $object );
var_dump( $reference->get() ); # NULL
```

Якщо зберегти результат `get()` у звичайну змінну, вона знову утримуватиме об'єкт. Слабкою залишається сама `WeakReference`, а не всі посилання, які ми з неї отримали.

<a id="weak-map"></a>

## Кеш, який не утримує об’єкт заради ключа

**PHP 8.0+ | Ядро** [Документація PHP](https://www.php.net/manual/en/class.weakmap.php)

`WeakMap` дозволяє прив'язати до об'єкта додаткові дані, наприклад результат обчислення, і не утримувати сам об'єкт заради кешу. Об'єкт використовується як ключ. Коли він більше нікому не потрібен і знищується, його запис зникає з `WeakMap` автоматично.

```php
$cache = new WeakMap();
$object = new stdClass();
$cache[$object] = ['rendered' => 'ready'];
var_dump( count($cache) ); # int(1)
unset( $object );
var_dump( count($cache) ); # int(0)
```

У прикладі після `unset()` кількість записів змінюється з одного на нуль. Але значення у `WeakMap` утримуються звичайними посиланнями. Якщо саме збережене значення посилається на свій ключ, воно може залишити об'єкт у пам'яті й запис не зникне.

<a id="fibers"></a>

## Пауза й продовження функції через `Fiber`

**PHP 8.1+ | Ядро** [Документація PHP](https://www.php.net/manual/en/language.fibers.php)

`Fiber` дозволяє поставити виконання функції на паузу й потім продовжити з того самого місця. Зберігається й ланцюжок вкладених викликів, тому призупинитися можна не лише в самій зовнішній функції. Тут `start()` доходить до `suspend()` і віддає назовні рядок `'waiting'`.

```php
$fiber = new Fiber( function(): int
{
	$value = Fiber::suspend( 'waiting' );
	return $value * 2;
} );

echo $fiber->start(), "\n"; # waiting
var_dump( $fiber->resume(21) ); # NULL: функція вже завершилася
var_dump( $fiber->getReturn() ); # int(42)
```

Потім `resume(21)` продовжує виконання: усередині значення `21` стає результатом `suspend()`. Функція повертає `42`, але її остаточний результат читається через `getReturn()`, тому сам `resume()` тут дає `null`. Fiber не перемикає роботу самостійно: без планувальника й неблокувального введення-виведення звичайна блокувальна операція все одно зупинить виконання.

<a id="preloading"></a>

## Попереднє завантаження сталого коду

**PHP 7.4+ | OPcache** [Документація PHP](https://www.php.net/manual/en/opcache.preloading.php)

Якщо вибрані функції й класи потрібні постійно, їх можна завантажити заздалегідь під час запуску процесу. В `opcache.preload` задаємо шлях до PHP-скрипту, який підготує цей код один раз. У прикладі такий скрипт компілює файл із класом, щоб його оголошення були доступні наступним запитам.

<!-- example: fragment -->
```php
# Цей preload.php вказаний в opcache.preload у php.ini.
opcache_compile_file( __DIR__ . '/src/User.php' );
```

У Windows preloading не підтримується. І заміна попередньо завантаженого файлу сама собою не оновить оголошення: після зміни такого коду потрібно перезапустити процес.

<a id="jit"></a>

## Чим відрізняються JIT і OPcache

**PHP 8.0+ JIT | OPcache** [Документація PHP](https://www.php.net/manual/en/opcache.configuration.php)

OPcache зберігає вже скомпільований байткод, щоб PHP не компілював його заново. JIT вирішує іншу частину задачі: може перевести відповідні ділянки виконання в машинний код. У прикладі читаємо стан OPcache й беремо дані про JIT, якщо вони взагалі є.

```php
$status = opcache_get_status( false );
$jit = ($status === false) ? null : ($status['jit'] ?? null);
var_dump( $jit ); # Результат залежить від поточного середовища.
```

Користь JIT залежить від навантаження, а доступність від збірки й налаштувань. Сам факт його наявності ще не означає прискорення конкретного коду. Під час вимірювання в CLI окремо перевіряємо `opcache.enable_cli` і параметри JIT, інакше можна вимірювати зовсім інше середовище.

<a id="ffi"></a>

## Робота з C через `FFI`

**PHP 7.4+ | FFI** [Документація PHP](https://www.php.net/manual/en/book.ffi.php)

`FFI` дозволяє описувати типи й функції C та працювати з ними з PHP. Це потрібно, коли потрібне пряме звернення до нативного коду. Тут приклад мінімальний, без завантаження бібліотеки: створюємо значення типу C `int`, записуємо в нього `42` і читаємо назад.

<!-- example: fragment -->
```php
$ffi = FFI::cdef();
$value = $ffi->new( 'int' );
$value->cdata = 42;
var_dump( $value->cdata ); # int(42)
```

Доступ може обмежуватися налаштуванням `ffi.enable`. Під час роботи з C неправильний опис функції або помилка звернення до пам'яті може завершити весь процес, тому звичайні гарантії безпеки PHP тут уже не рятують.

<a id="ini-quantities"></a>

## Розбір розмірів із `php.ini`

**PHP 8.2+ | Ядро** [Документація PHP](https://www.php.net/manual/en/function.ini-parse-quantity.php)

Значення на кшталт `128M` із `php.ini` не можна просто привести до `int`, якщо потрібен розмір у байтах. Для цього є `ini_parse_quantity()`: він розуміє множники `K`, `M` і `G`, де кожен крок дорівнює 1024. У прикладі видно, які числа виходять із `128M` і `512K`.

```php
var_dump( ini_parse_quantity('128M') ); # int(134217728)
var_dump( ini_parse_quantity('512K') ); # int(524288)
var_dump( ini_parse_quantity('-1') ); # int(-1)
```

Спеціальні значення теж зберігаємо за змістом налаштування: наприклад, `-1` у `memory_limit` не є розміром у байтах. Неправильний рядок може викликати попередження й усе ж повернути число за його початком, тому це не сувора перевірка довільного введення.

<a id="measure-memory"></a>

## Вимірюємо пік пам’яті окремого етапу

**PHP 8.2+ | Ядро** [Документація PHP](https://www.php.net/manual/en/function.memory-reset-peak-usage.php)

Якщо до потрібної ділянки вже була важка операція, загальний пік пам'яті показуватиме її результат. `memory_reset_peak_usage()` дозволяє почати відлік піка заново перед окремим етапом. Тут скидаємо його, створюємо рядок і рахуємо, наскільки максимум виріс відносно початкового використання.

```php
# Попередні операції не мають задавати пік цього етапу.
memory_reset_peak_usage();
$before = memory_get_usage();
$buffer = str_repeat( 'x', 1_000_000 );
$peak_growth = memory_get_peak_usage() - $before;
var_dump( $peak_growth ); # Зростання піка в байтах відносно початку етапу.
unset( $buffer );
```

Скидання не звільняє пам'ять і не обнуляє саме використання процесу. `memory_get_peak_usage()` усе ще повертає абсолютну кількість байтів, тому для зростання в прикладі віднімаємо `$before`.

<a id="ini-and-cli"></a>

## Запасні значення в `php.ini`, права журналу й `php -l`

**PHP 8.2+ права журналу / PHP 8.3+ запасні значення ini й перевірка кількох файлів** [Документація PHP](https://www.php.net/manual/en/configuration.file.php)

З PHP 8.3 у `php.ini` можна вказати запасне значення змінної середовища: тут без `PHP_MAX_EXECUTION_TIME` візьметься `30`. У тій самій версії `php -l` навчився перевіряти кілька файлів одним викликом. А `error_log_mode`, доступний з PHP 8.2, задає права під час створення файлу журналу.

```ini
max_execution_time = ${PHP_MAX_EXECUTION_TIME:-30}
error_log_mode = 0640
```

```sh
php -l first.php second.php
```

`0640` у прикладі задає Unix-права. На Windows доступ до файлу налаштовується через ACL окремо, цей запис таких прав не замінює.

<a id="extension-capabilities"></a>

## Перевірка можливостей збірки: AVIF у GD

**PHP 8.1+ AVIF API | gd** [Документація PHP](https://www.php.net/manual/en/function.imageavif.php)

Функції роботи з AVIF є в GD з PHP 8.1, але конкретна збірка GD може бути без цього кодека. Тому спочатку перевіряємо `imagetypes() & IMG_AVIF` і лише потім читаємо файл. У прикладі після читання зберігаємо зображення в інший AVIF-файл.

<!-- example: fragment -->
```php
# Обидва шляхи локальні й уже перевірені, не беремо їх напряму із запиту.
if( !(imagetypes() & IMG_AVIF) )
	throw new RuntimeException( 'AVIF support is unavailable' );

$image = imagecreatefromavif( $source_path );

if( $image === false )
	throw new RuntimeException( 'Cannot decode AVIF' );

imageavif( $image, $target_path, 80 );
```

Версія PHP й наявність потрібного методу ще не гарантують підтримку самого формату. Перевірка поточної збірки допомагає відрізнити відсутність кодека від помилки читання конкретного файлу.

<a id="monotonic-time"></a>

## Вимірюємо час роботи через `hrtime()`

**PHP 7.3+ | standard** [Документація PHP](https://www.php.net/manual/en/function.hrtime.php)

Для тривалості операції зручніше `hrtime()`: цей годинник іде послідовно й не залежить від переведення календарного часу. Беремо значення до обчислення й після, віднімаємо одне від іншого та переводимо наносекунди в мілісекунди. Це час виконання операції, а не дата для журналу.

```php
$started_at = hrtime( true );
$digest = hash( 'sha256', str_repeat('x', 100000) );
$finished_at = hrtime( true );

if( $started_at === false || $finished_at === false )
	throw new RuntimeException( 'Clock unavailable' );

$elapsed_ms = ($finished_at - $started_at) / 1000000;
var_dump( $elapsed_ms ); # Мілісекунди виконання; під час кожного запуску число своє.
```

З `true` результат має тип `int` на 64-бітній платформі й `float` на 32-бітній. Одиниця вимірювання в наносекундах не означає, що обладнання справді розрізняє кожну наносекунду. Отримані значення перевіряємо на `false`, як у прикладі.

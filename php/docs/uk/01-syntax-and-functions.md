<a id="null-coalescing"></a>
## Значення за замовчуванням через ??

**PHP 7.0+ | Ядро**

Використовуйте `??`, коли відсутнє значення та `null` означають «взяти значення за замовчуванням». Наявні `0`, `false` і порожній рядок зберігаються. Це зручно для налаштувань і необов’язкових полів масиву.

```php
$config = ['limit' => 0, 'label' => null];

var_dump( $config['limit'] ?? 20 );
var_dump( $config['label'] ?? 'Untitled' );
var_dump( $config['missing'] ?? 'Fallback' );
# int(0), string(8) "Untitled", string(8) "Fallback"
```

На відміну від `?:`, оператор не замінює кожне хибне значення. Він також не розрізняє відсутній ключ і ключ із `null`; якщо різниця важлива, потрібен `array_key_exists()`. Поєднуючи `??` зі склеюванням рядків, явно ставте дужки.

[Документація PHP](https://www.php.net/manual/en/language.operators.comparison.php#language.operators.comparison.coalesce)

<a id="null-coalescing-assignment"></a>
## Доповнення налаштувань через ??=

**PHP 7.4+ | Ядро**

`??=` записує значення за замовчуванням назад у змінну або елемент масиву. Він доречний, коли наступний код має бачити доповнені налаштування, а не лише тимчасове запасне значення.

```php
$config = ['retries' => 0];
$config['timeout'] ??= 30;
$config['retries'] ??= 3;

echo $config['timeout'], ':', $config['retries'];
# 30:0
```

Елемент із `null` також буде замінено. Права частина обчислюється лише тоді, коли потрібне присвоєння, тому там може бути й дорожче обчислення значення за замовчуванням.

[Документація PHP](https://www.php.net/manual/en/language.operators.assignment.php)

<a id="spaceship"></a>
## Сортування оператором <=>

**PHP 7.0+ | Ядро**

Функція порівняння для сортування має повертати від’ємне число, нуль або додатне число. `<=>` дає саме такий результат: `-1`, `0` або `1`. Це прибирає ланцюжок умов із функції порівняння.

```php
$rows = [['score' => 8], ['score' => 2], ['score' => 5]];

usort( $rows, function( array $left, array $right ): int
{
	return $left['score'] <=> $right['score'];
} );

echo implode( ',', array_column($rows, 'score') );
# 2,5,8
```

Для спадного порядку поміняйте операнди місцями. Якщо типи можуть різнитися, спочатку нормалізуйте дані: `<=>` використовує правила порівняння PHP і не є оператором строгої рівності. Повернення лише `true` або `false` не замінює тристороннє порівняння.

[Документація PHP](https://www.php.net/manual/en/language.operators.comparison.php)

<a id="arrow-functions"></a>
## Стрілкові функції та захоплені значення

**PHP 7.4+ | Ядро**

`fn` зручна для короткого перетворення з одним виразом. Змінні із зовнішньої області захоплюються за значенням під час створення функції; явний список `use` не потрібен.

```php
$factor = 10;
$multiply = fn( int $value ): int => $value * $factor;
$factor = 20;

echo $multiply( 3 );
# 30
```

Для кількох дій використовуйте звичайне замикання, а для зміни зовнішньої змінної потрібне `use( &$value )`. Захоплення об’єкта за значенням усе ще посилається на той самий об’єкт, а не створює глибоку копію. `static fn` також не прив’язує `$this` автоматично.

[Документація PHP](https://www.php.net/manual/en/functions.arrow.php)

<a id="named-arguments"></a>
## Іменовані аргументи

**PHP 8.0+ | Ядро**

Назви параметрів роблять зміст виклику зрозумілим і дозволяють пропускати необов’язкові параметри. Це особливо зручно для кількох булевих опцій або функцій із багатьма значеннями за замовчуванням.

```php
function describe_item( string $name, bool $active = true, int $limit = 20 ): string
{
	return $name . ':' . $limit;
}

echo describe_item( 'Report', limit: 5 );
# Report:5
```

Позиційні аргументи мають іти перед іменованими. Назви параметрів стають частиною інтерфейсу виклику: перейменування `$limit` може зламати код із `limit:`. У публічних функціях обирайте зрозумілі стабільні назви.

[Документація PHP](https://www.php.net/manual/en/functions.arguments.php#functions.named-arguments)

<a id="unpacking-named-arguments"></a>
## Рядкові ключі стають іменованими аргументами

**PHP 8.0+ | Ядро**

Під час розпакування масиву у виклик рядкові ключі сприймаються як назви параметрів. Це важливо і для перенесення коду з `call_user_func_array()` на PHP 8: асоціативний масив уже не є лише позиційним списком.

```php
function format_range( int $start, int $end ): string
{
	return $start . '-' . $end;
}

$arguments = ['end' => 9, 'start' => 3];
echo format_range( ...$arguments );
# 3-9
```

Невідомі назви або повторне передавання одного параметра спричиняють помилку. Якщо ключі є довільними мітками, а потрібен позиційний порядок, свідомо використайте `array_values()`. Не розпаковуйте неперевірені дані запиту прямо у функцію застосунку.

[Документація PHP](https://www.php.net/manual/en/function.call-user-func-array.php)

<a id="named-after-unpacking"></a>
## Іменовані аргументи після розпакування

**PHP 8.1+ | Ядро**

Виклик може розпакувати підготовлений список, а потім передати решту параметрів за назвою. Це зручно, коли конкретному виклику потрібна явна опція на додачу до спільних позиційних аргументів.

```php
function join_parts( string $left, string $right, string $separator = '/' ): string
{
	return $left . $separator . $right;
}

$parts = ['docs', 'types'];
echo join_parts( ...$parts, separator: ':' );
# docs:types
```

Іменований аргумент наприкінці не може повторно задавати параметр, який уже переданий розпакованим масивом. Це можливість аргументів виклику, окрема від розпакування масивів в інший масив.

[Документація PHP](https://www.php.net/manual/en/functions.arguments.php)

<a id="match"></a>
## match повертає значення та порівнює строго

**PHP 8.0+ | Ядро**

`match` зручний, коли невеликий набір вхідних значень визначає один результат. Кожна вибрана гілка є виразом, а порівняння строге, тому `1` і `'1'` можуть давати різні результати.

```php
$status = '1';
$label = match( $status )
{
	1 => 'numeric',
	'1' => 'text',
	2, 3 => 'other known state',
	default => 'unknown',
};

echo $label;
# text
```

Переходу в наступну гілку та `break` немає. Якщо немає відповідної гілки й `default`, PHP викидає `UnhandledMatchError`. Відсутність `default` може бути свідомою, коли потрібно обробляти кожен випадок enum. Замінюючи `switch`, перевірте його попереднє нестроге порівняння.

[Документація PHP](https://www.php.net/manual/en/control-structures.match.php)

<a id="nullsafe"></a>
## Ланцюжок необов’язкових об’єктів через ?->

**PHP 8.0+ | Ядро**

`?->` зупиняє ланцюжок доступу до об’єктів, якщо лівий операнд дорівнює `null`. Це короткий запис ситуації, коли пов’язаний об’єкт справді може бути відсутнім.

```php
class Profile
{
	public function city(): string
	{
		return 'Kyiv';
	}
}

$profile = null;
echo $profile?->city() ?? 'Not provided';
# Not provided
```

Ставте `?->` на кожному кроці, який може бути `null`. Оператор не перевіряє назви властивостей, не перетворює `false` на `null` і не приховує винятки справжнього методу. Він призначений для читання: присвоєння через такий ланцюжок не підтримується. Відсутність обов’язкового зв’язку краще позначати явною помилкою.

[Документація PHP](https://www.php.net/manual/en/language.oop5.basic.php#language.oop5.basic.nullsafe)

<a id="throw-expression"></a>
## throw усередині виразу

**PHP 8.0+ | Ядро**

Відсутнє обов’язкове значення може одразу спричинити виняток у виразі, який його читає. Використовуйте це для коротких перевірок із очевидним змістом.

```php
$config = ['token' => 'local-example'];
$token = $config['token'] ?? throw new InvalidArgumentException( 'Token is required' );

echo $token;
# local-example
```

Наведена перевірка приймає порожній рядок, адже `??` перевіряє лише відсутність і `null`. Якщо порожній токен неприпустимий, перевірте вміст окремо. Для кількох кроків перевірки або докладнішої помилки використовуйте звичайний `if`.

[Документація PHP](https://www.php.net/exceptions)

<a id="closure-from-callable"></a>
## Перетворення callable через Closure::fromCallable()

**PHP 7.1+ | Ядро**

`Closure::fromCallable()` перетворює наявний callable на `Closure` і перевіряє можливість виклику в поточній області видимості. Це корисно, коли callback надходить як назва функції чи масив методу, а API зберігає замикання.

```php
function add_prefix( string $name ): string
{
	return 'note:' . $name;
}

$format = Closure::fromCallable( 'add_prefix' );
echo $format( 'types' ), PHP_EOL;
var_dump( $format instanceof Closure );
# note:types
# bool(true)
```

Некоректний або недоступний callable спричиняє `TypeError` під час перетворення. Отримане замикання зберігає контекст видимості callable, а не робить довільний приватний метод публічним. Із PHP 8.1 [синтаксис посилання на функцію](#first-class-callables) дає ту саму поведінку для callable, записаного безпосередньо в коді.

[Документація PHP](https://www.php.net/manual/en/closure.fromcallable.php)

<a id="first-class-callables"></a>
## Синтаксис посилання на функцію: function_name(...)

**PHP 8.1+ | Ядро**

Буквальний запис `...` створює `Closure` замість виклику функції. Він зручний для передавання відомої функції або методу як callback; доступність перевіряється під час створення.

```php
$normalize = trim(...);
$values = array_map( $normalize, [' one ', ' two '] );

echo implode( ',', $values );
# one,two
```

`$service->handle(...)` також створює посилання на метод у поточній області видимості. Це не розпакування аргументів: після крапок немає масиву. Запис не можна поєднати з `?->` або використати як `new ClassName(...)` для створення callback конструктора.

[Документація PHP](https://www.php.net/manual/en/functions.first_class_callable_syntax.php)

<a id="pipe"></a>
## Оператор послідовної обробки |>

**PHP 8.5+ | Ядро**

Оператор передає значення ліворуч у callable праворуч, а результат виклику стає значенням усього виразу. Послідовність невеликих перетворень читається в порядку виконання.

```php
$slug = ' PHP Notes '
	|> trim(...)
	|> strtolower(...)
	|> (fn( string $text ): string => str_replace(' ', '-', $text));

echo $slug;
# php-notes
```

Callable має приймати передане значення як аргумент. Для функцій із додатковими аргументами або іншою позицією значення використовуйте невелике замикання. Ланцюжок виконується синхронно, не обробляє помилки замість вас і не робить довге перетворення автоматично зрозумілим.

[Документація PHP](https://www.php.net/manual/en/language.operators.functional.php)

<a id="closures-in-constant-expressions"></a>
## Callback у константних виразах

**PHP 8.5+ | Ядро**

Посилання на функції та статичні замикання з певними обмеженнями тепер дозволені там, де PHP потребує константного виразу, зокрема у значеннях параметрів за замовчуванням і константах. Callback може отримати корисне початкове значення без nullable-параметра й додаткової гілки ініціалізації.

```php
function normalize_name( string $name, Closure $normalizer = trim(...) ): string
{
	return $normalizer( $name );
}

echo normalize_name( ' Ada ' );
# Ada
```

Це не дозволяє довільні виклики функцій усередині констант. Вираз створює callable, а його тіло виконується пізніше під час виклику. Замикання в константних виразах мають бути статичними й не можуть захоплювати зовнішні змінні через `use`.

[Документація PHP](https://wiki.php.net/rfc/closures_in_const_expr)

<a id="recursive-closures"></a>
## Рекурсія через Closure::getCurrent()

**PHP 8.5+ | Ядро**

Замикання може отримати власний екземпляр, який зараз виконується. Завдяки цьому не потрібно захоплювати за посиланням змінну, у яку його буде записано, лише заради рекурсивного виклику.

```php
$factorial = static function( int $value ): int
{
	if( $value < 0 )
		throw new InvalidArgumentException( 'Expected a non-negative integer' );

	if( $value <= 1 )
		return 1;

	$current = Closure::getCurrent();
	return $value * $current( $value - 1 );
};

echo $factorial( 5 );
# 120
```

Виклик `Closure::getCurrent()` поза замиканням викидає `Error`. Він спрощує посилання, а не алгоритм: глибока рекурсія все ще витрачає ресурси, а значення факторіала швидко виходить за межі цілого числа.

[Документація PHP](https://www.php.net/manual/en/closure.getcurrent.php)

<a id="trailing-commas"></a>
## Кінцева кома у викликах та оголошеннях

**PHP 7.3+ | Ядро**

PHP 7.3 дозволяє кінцеву кому у виклику функції або методу. PHP 8.0 також дозволяє її в оголошеннях параметрів і списках `use` замикань. Завдяки цьому додавання рядка в багаторядковий список дає меншу різницю у Git.

```php
# This call syntax works from PHP 7.3.
echo implode(
	',',
	['one', 'two'],
);
# one,two
```

Кінцева кома не передає додатковий аргумент. Мінімальна версія залежить від місця коми: виклик та оголошення функції отримали підтримку в різних випусках.

[Документація PHP](https://www.php.net/manual/en/functions.arguments.php)

<a id="numeric-literals"></a>
## Читабельні числові літерали

**PHP 7.4+ | Ядро**

Роздільники цифр роблять ліміт або бітову маску зрозумілішими без зміни значення. PHP 8.1 додає явний префікс вісімкових чисел `0o`, тож більше не потрібно покладатися на непомітний початковий нуль.

```php
$max_bytes = 10_485_760;
$mask = 0b1111_0000;

echo $max_bytes, ':', $mask;
# 10485760:240
```

У PHP 8.1+ `0o644` означає те саме, що `0644`, тобто десяткове `420`. Роздільники ставлять між цифрами; це синтаксис вихідного коду, а не формат, який розуміє будь-яке перетворення рядка на число.

[Документація PHP](https://www.php.net/manual/en/language.types.integer.php)

<a id="group-use"></a>
## Групування імпортів простору імен

**PHP 7.0+ | Ядро**

Кілька назв з одного простору імен можуть мати спільний префікс у конструкції `use`. Це зручно, коли файл використовує кілька пов’язаних класів застосунку.

```php
use App\Report\{CsvWriter, JsonWriter};

echo CsvWriter::class, PHP_EOL;
echo JsonWriter::class;
# App\Report\CsvWriter
# App\Report\JsonWriter
```

Приклад виводить назви класів, тому не потребує створення їхніх об’єктів. Сам імпорт не завантажує і не створює клас. Не варто збирати величезну групу лише заради меншої кількості рядків `use`.

[Документація PHP](https://www.php.net/manual/en/language.namespaces.importing.php)

<a id="closure-call"></a>
## Тимчасова прив’язка замикання через call()

**PHP 7.0+ | Ядро**

`Closure::call()` викликає замикання з тимчасовим об’єктом `$this` та областю видимості його класу. Це буває корисним у контрольованому коді перевірки, коли постійно переприв’язане замикання не потрібне.

```php
class Counter
{
	private $value = 7;
}

$read = function(): int
{
	return $this->value;
};

echo $read->call( new Counter() );
# 7
```

Статичне замикання не можна прив’язати до `$this`. Доступ до приватного стану має бути свідомим прийомом для інструментів або тестів, а не заміною звичайного публічного інтерфейсу об’єкта.

[Документація PHP](https://www.php.net/manual/en/closure.call.php)

<a id="static-initializers"></a>
## Вирази в ініціалізаторах статичних локальних змінних

**PHP 8.3+ | Ядро**

Статичну локальну змінну тепер можна ініціалізувати викликом функції або іншим динамічним виразом. Ініціалізація відбувається, коли виконання вперше доходить до неї; наступні виклики використовують збережене значення.

```php
function next_number(): int
{
	static $number = strlen( 'seed' );
	return ++$number;
}

echo next_number(), ':', next_number();
# 5:6
```

Це зручно для невеликого локального кешу. Такий запис не створює кеш, спільний для окремих PHP-запитів. У довготривалому worker стан функції може жити значно довше, тому даним конкретного запиту потрібен явний контроль часу життя.

[Документація PHP](https://wiki.php.net/rfc/arbitrary_static_variable_initializers)

<a id="exit-callable"></a>
## exit() і die() поводяться ближче до звичайних функцій

**PHP 8.4+ | Ядро**

`exit()` тепер можна використовувати як callable, а його аргумент підпорядковується звичайним правилам типів, зокрема `strict_types`. Ціле число задає код завершення процесу; рядок виводиться перед завершенням.

```php
$terminate = exit(...);

var_dump( $terminate instanceof Closure );
# bool(true)
# Calling $terminate(0) would end this script.
```

Приклад отримує callable без завершення процесу. Старий код, який передає масив або інший неприпустимий тип, потрібно виправити: PHP тепер викидає `TypeError`, а не покладається на старе перетворення. `die()` є псевдонімом із тими самими правилами.

[Документація PHP](https://www.php.net/manual/en/migration84.incompatible.php)

<a id="casts-in-constant-expressions"></a>
## Приведення типу в константних виразах

**PHP 8.5+ | Ядро**

Явне приведення типу тепер дозволене в константних виразах. Обчислювана константа може прямо задавати потрібне представлення без окремо підготовленого літерала.

```php
const WHOLE_SECONDS = (int)3.9;

echo WHOLE_SECONDS;
# 3
```

Змінилося те, які вирази можна оголосити, а не правила перетворення: приведення float до int відкидає дробову частину. Приведення не є перевіркою вхідних даних, а правильний літерал на кшталт `const RETRIES = 3` його не потребує.

[Документація PHP](https://www.php.net/manual/en/language.constants.syntax.php)

<a id="global-constant-attributes"></a>
## Атрибути глобальних констант

**PHP 8.5+ | Ядро**

Атрибути тепер можна додавати до констант поза класом, оголошених через `const`. Практичний вбудований приклад: позначити стару константу налаштувань як застарілу та вказати заміну.

```php
#[Deprecated( 'Use DEFAULT_PAGE_SIZE' )]
const OLD_PAGE_SIZE = 20;
const DEFAULT_PAGE_SIZE = 20;

echo DEFAULT_PAGE_SIZE;
# 20
```

Читання `OLD_PAGE_SIZE` створило б повідомлення про застарілість. Цей синтаксис не застосовується до констант від `define()`. У власних атрибутах дозвольте `Attribute::TARGET_CONSTANT` і читайте метадані через reflection; PHP не вигадує поведінку для метаданих застосунку.

[Документація PHP](https://www.php.net/manual/en/migration85.new-features.php)
